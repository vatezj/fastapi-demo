# 任务步骤和验证详细说明

## 📋 概述

在游赚项目中，每个任务都包含**多个步骤**和**多个验证要求**，用户需要按顺序完成所有步骤，并满足所有验证要求才能获得佣金。

## 🔄 任务步骤 (yozuan_task_step)

### 设计原则
- **一对多关系**: 一个任务可以有多个步骤
- **顺序执行**: 步骤按 `step_order` 字段排序，用户必须按顺序完成
- **灵活类型**: 每个步骤可以是链接、图片或文本说明
- **必填控制**: 通过 `is_required` 字段控制步骤是否必填

### 步骤类型说明

#### 1. 链接类型 (link)
```sql
-- 示例：下载APP步骤
INSERT INTO yozuan_task_step VALUES
(1, 1, 1, '下载APP', '从应用商店下载指定APP', 'link', 'https://example.com/download', 1, NOW());
```
- **用途**: 引导用户访问特定链接
- **内容**: 下载链接、注册链接、活动链接等
- **验证**: 用户需要点击链接并完成相应操作

#### 2. 图片类型 (image)
```sql
-- 示例：查看操作说明步骤
INSERT INTO yozuan_task_step VALUES
(2, 1, 2, '查看说明', '查看详细操作说明图片', 'image', '/images/instruction.jpg', 1, NOW());
```
- **用途**: 提供操作说明、界面截图等
- **内容**: 操作指南图片、界面截图、流程说明图
- **验证**: 用户需要查看图片内容

#### 3. 文本类型 (text)
```sql
-- 示例：填写信息步骤
INSERT INTO yozuan_task_step VALUES
(3, 1, 3, '填写信息', '请按照要求填写相关信息', 'text', '请填写：姓名、手机号、身份证号', 1, NOW());
```
- **用途**: 提供文字说明、填写要求等
- **内容**: 操作说明、填写要求、注意事项
- **验证**: 用户需要阅读并理解文本内容

## ✅ 任务验证 (yozuan_task_verification)

### 设计原则
- **一对多关系**: 一个任务可以有多个验证要求
- **全部完成**: 用户必须完成所有验证要求才能通过审核
- **灵活组合**: 支持图片、文本或两者都需要的验证方式
- **驳回重试**: 验证失败后可以重新提交

### 验证类型说明

#### 1. 仅图片验证 (image)
```sql
-- 示例：上传截图验证
INSERT INTO yozuan_task_verification VALUES
(1, 1, '注册完成验证', '请提供注册成功的截图', 'image', 1, 0, NULL, NOW());
```
- **用途**: 验证用户完成特定操作
- **要求**: 用户必须上传相关截图
- **常见场景**: 注册成功截图、操作完成截图、结果展示截图

#### 2. 仅文本验证 (text)
```sql
-- 示例：填写体验感受
INSERT INTO yozuan_task_verification VALUES
(4, 1, '任务完成确认', '请描述完成任务的感受', 'text', 0, 1, '请简单描述使用体验', NOW());
```
- **用途**: 收集用户反馈、验证理解程度
- **要求**: 用户必须填写相关文本内容
- **常见场景**: 使用体验描述、问题反馈、建议意见

#### 3. 混合验证 (both)
```sql
-- 示例：既需要图片又需要文本
INSERT INTO yozuan_task_verification VALUES
(5, 1, '综合验证', '请上传操作截图并描述体验', 'both', 1, 1, '请上传截图并描述使用感受', NOW());
```
- **用途**: 综合验证用户完成情况
- **要求**: 用户必须同时上传图片和填写文本
- **常见场景**: 复杂任务的综合验证

### 实际应用示例

#### 完整验证要求示例
```sql
-- 一个任务包含4个验证要求

(1, 1, '注册完成验证', '请提供注册成功的截图', 'image', 1, 0, NULL, NOW()),

(4, 1, '任务完成确认', '请描述完成任务的感受', 'text', 0, 1, '请简单描述使用体验', NOW());
```

## 🔄 完整业务流程示例

### 任务发布阶段
1. **创建任务**: 发布者创建任务基本信息
2. **添加步骤**: 添加多个任务步骤，设置顺序和类型
3. **设置验证**: 设置多个验证要求，定义验证方式
4. **发布上线**: 任务上线等待用户接单

### 任务执行阶段
1. **用户接单**: 用户报名参与任务
2. **按序执行**: 用户按照步骤顺序完成各项操作
3. **收集材料**: 用户在执行过程中收集验证材料
4. **提交验证**: 用户提交所有验证要求的内容

### 任务审核阶段
1. **发布者审核**: 发布者检查所有验证内容
2. **全部通过**: 所有验证要求都通过才算完成
3. **整体驳回**: 任何验证失败都整体驳回，用户重新提交所有验证
4. **资金分配**: 验证全部通过后分配佣金

## 📊 数据结构关系

```
yozuan_task (任务主表)
    ↓ 1:N
yozuan_task_step (任务步骤表)
    ├── step_order: 步骤顺序
    ├── step_type: 步骤类型 (link/image/text)
    └── step_content: 步骤内容

yozuan_task (任务主表)
    ↓ 1:N
yozuan_task_verification (任务验证表)
    ├── verification_type: 验证类型 (image/text/both)
    ├── image_required: 是否需要图片
    └── text_required: 是否需要文本

yozuan_task_verification (任务验证表)
    ↓ 1:N
yozuan_task_verification_submit (验证提交表)
    ├── submit_data: 一次性提交所有验证内容（JSON格式）
    └── review_status: 审核状态

注意：验证提交是一次性提交所有验证内容，不是逐个提交

## 💡 设计优势

### 1. **灵活性**
- 支持不同类型的任务需求
- 可以设置任意数量的步骤和验证
- 验证方式可以灵活组合

### 2. **可扩展性**
- 新增验证类型容易
- 支持复杂的任务流程
- 便于功能迭代升级

### 3. **用户体验**
- 步骤清晰明确
- 验证要求具体
- 操作流程顺畅

### 4. **管理便利**
- 发布者可以精细控制任务要求
- 审核标准明确
- 便于质量管控

## 🚀 使用建议

### 1. **步骤设计**
- 步骤数量控制在3-8个之间
- 每个步骤要求明确具体
- 步骤之间逻辑连贯

### 2. **验证设置**
- 验证要求具体可操作
- 避免过于复杂的验证
- 提供清晰的示例说明

### 3. **用户体验**
- 步骤说明简洁明了
- 验证要求容易理解
- 提供必要的操作指导

这样的设计确保了每个任务都有完整的执行流程和验证机制，用户需要认真完成所有要求才能获得佣金，保证了任务质量和用户体验。
